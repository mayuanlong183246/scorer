## 第一部分：工作原理

### 1. 核心思想（一句话）

MPPI 不求解复杂的优化方程，而是**"暴力采样 + 加权平均"**：

```
1. 用运动模型随机生成 N 条未来轨迹（采样）
2. 每条轨迹用一个"代价函数"打分（critics）
3. 分数越好权重越大（temperature 控制权重集中度）
4. 加权平均所有轨迹的第一步控制量 → 执行
5. 每 0.05s 重算一次（滚动时域）
```

**为什么这个朴素思想有效**：它把"最优控制"这个困难的优化问题，转化成了"蒙特卡洛估计期望"这个可以并行、可以任意模型、可以任意代价函数的问题。

---

### 2. 数学框架

MPPI 的完整推导基于**信息论 + 重要性采样**，核心链条如下。

#### 2.1 系统模型

离散时间随机动力学：

```
x_{t+1} = F(x_t, v_t),   v_t ~ N(u_t, Σ)
```

- `x_t`：状态（位姿、速度）
- `v_t`：实际控制输入（随机），服从以 `u_t` 为均值、`Σ` 为协方差的高斯分布
- 我们的 `motion_model: "Omni"` 就是 `F`，描述全向车如何从当前状态 + 速度指令推到下一状态

#### 2.2 轨迹与代价

一条采样轨迹 τ（时域 T 内）：

```
τ = (x_0, v_0, x_1, v_1, ..., x_T, v_T)

轨迹代价：S(τ) = Σ_{t=0}^{T} [ C(x_t) + λ·u_t^T Σ^{-1} v_t ]
                   └── 状态代价 ──┘   └── 控制代价（正则项）──┘
```

- `C(x_t)`：状态代价，由 7 个 critics 累加（GoalCritic、PathFollowCritic、ObstaclesCritic 等）
- `λ`：就是 `temperature`（温度参数，见下文）
- `u_t^T Σ^{-1} v_t`：控制代价，惩罚控制量偏离均值

#### 2.3 最优控制分布（信息论视角）

MPPI 的关键洞察：**不是找一条最优轨迹，而是找最优的"控制分布"**。

用 KL 散度约束新分布不要偏离旧分布太远：

```
u* = argmin_u  E[ S(τ) ]   +  λ·KL( q_u || q_u_prev )
                    └ 期望代价 ┘      └ 分布距离惩罚 ┘
```

解这个带 KL 约束的优化，得到**闭式解**（这就是 MPPI 的威力——不需要迭代求解）：

```
u* = ∫ p(τ) · w(τ) · v_t dτ
```

其中权重：

```
w(τ) = exp( -S(τ) / λ )     ← temperature λ 在这里
```

**这就是 MPPI 最核心的公式**：最优控制 = 所有采样轨迹的**加权平均**，权重由代价的指数函数决定。

---

### 3. 采样策略

#### 3.1 高斯噪声采样

每个采样轨迹的控制输入由"基准控制 + 高斯噪声"生成：

```
v_t = u_t + ε_t,   ε_t ~ N(0, Σ)
```

`vx_std: 0.6, vy_std: 0.6, wz_std: 0.2` 就是 `Σ` 对角线上的标准差，决定采样轨迹的"发散程度"。

#### 3.2 采样数量与并行

`batch_size: 1200` = 每次采 1200 条轨迹。MPPI 的美妙之处：**1200 条轨迹的模拟和打分相互独立**，可以在 GPU 上并行（原始论文标题 "Parallel Computation" 就强调这一点）。

#### 3.3 采样序列的时域展开

每条轨迹在时域 T 内展开（`time_steps × model_dt = 50 × 0.05 = 2.5s`），每一步用 `F` 前向模拟，累加代价得到 `S(τ)`。

---

### 4. 权重计算机制（重点）

权重公式：

```
w(τ) = exp( -S(τ) / λ )
```

这个指数函数是理解 MPPI 的关键。以 `temperature: 0.5` 举例：

| 轨迹代价 S(τ) | w(τ) = exp(-S/0.5) | 相对权重 |
|---|---|---|
| 很低（好轨迹） | exp(0) ≈ 1.0 | 主导 |
| 中等 | exp(-2) ≈ 0.135 | 较小 |
| 很高（差轨迹） | exp(-10) ≈ 0.000045 | 几乎忽略 |

**指数函数把代价差异"放大"成权重差异**，好轨迹的贡献被凸显，坏轨迹被抑制。这就是 MPPI 能自动"挑出"好轨迹的原因。

**temperature 的作用**：

```
λ 大（如 1.0）：exp(-S/λ) 衰减慢 → 权重平均化 → 优柔寡断 → 平滑但犹豫
λ 小（如 0.3）：exp(-S/λ) 衰减快 → 权重集中 → 果断激进 → 响应快但易抖
```

我们设 0.5 属于"偏果断"，注释写得很准确。

---

### 5. 迭代优化过程

虽然 MPPI 有闭式解，但工程上仍会做**多次迭代**（重要性采样的迭代改进）：

```
迭代 1：用当前控制 u 作为基准，采样 → 加权 → 得到 u_1
迭代 2：用 u_1 作为新基准，采样 → 加权 → 得到 u_2
...
```

我们的 `iteration_count: 1`，即只做一次（Nav2 默认也是 1）。提高迭代次数能收敛更准，但成倍增加计算量。

**完整执行循环**（对应 `controller_frequency: 20Hz`）：

```
每 0.05s 一次：
  1. 读当前状态 x
  2. 采样 batch_size 条轨迹
  3. 每条轨迹跑 critics 算 S(τ)
  4. 算权重 w(τ) = exp(-S/λ)
  5. 加权平均得到 u*
  6. 输出 u* 给 velocity_smoother → 底盘
```

---

### 6. 与其他 MPC 方法的区别与联系

| 维度 | 传统 MPC（DWA/TEB/MPC） | MPPI |
|---|---|---|
| **优化方式** | 解析求解 / 数值优化（梯度下降、二次规划） | **采样 + 加权平均**（蒙特卡洛） |
| **模型要求** | 需可微 / 线性化 | **任意模型**（黑盒也行） |
| **代价函数** | 需凸 / 可微 | **任意函数**（非凸、非光滑都行） |
| **全局最优** | 局部最优（依赖初值） | 接近全局（采样覆盖广） |
| **计算方式** | 串行，难并行 | **高度并行**（GPU 友好） |
| **速度** | 快（模型简单时） | 中（依赖 batch_size） |
| **处理复杂约束** | 需要专门处理 | 天然支持（写进代价即可） |

**联系**：三者都是**滚动时域优化（Receding Horizon）**——每步重算，只看未来 T 秒，执行第一步。区别只在"如何求解最优控制"。

**关键优势（为什么选 MPPI）**：MPPI 不需要模型可微、不需要代价函数凸，所以能塞进**任意复杂的打分项**——比如我们的 7 个 critics（目标、路径、障碍、对齐、约束），甚至将来可以加"避免碰撞动态障碍"这种非光滑代价。

## 第二部分：参数分析

### 参数全景表

| 参数 | 当前值 | 物理意义 | 所属环节 |
|---|---|---|---|
| `batch_size` | 1200 | 采样轨迹数量 N | 采样 |
| `time_steps` × `model_dt` | 50×0.05 | 预测时域 T | 采样 |
| `temperature` (λ) | 0.5 | 风险敏感/温度参数 | 权重 |
| `gamma` | 0.0 | 控制代价正则化系数 | 权重 |
| `vx/vy/wz_std` | 0.6/0.6/0.2 | 噪声协方差 Σ | 采样 |
| `iteration_count` | 1 | 重要性采样迭代次数 | 迭代 |
| `ax/ay/az_max` | 3.5 | 加速度物理约束 | 模型 |
| critics 的 `cost_weight` | 各异 | 各代价项权重 | 代价 |

---

### 1. 采样数量 `batch_size`

**物理意义**：蒙特卡洛估计的样本数 N。决定"加权平均"对真实期望的逼近程度。

**量化影响**：

```
估计误差 ∝ 1/√N

N=300  → 误差 ~5.8%
N=1200 → 误差 ~2.9%（当前值）
N=4800 → 误差 ~1.4%
```

| 增大 N | 减小 N |
|---|---|
| 轨迹估计更准、更稳 | 计算更快 |
| 更可能采样到好轨迹 | 估计方差大、指令抖动 |
| 计算量线性增加 | 采样可能漏掉关键轨迹 |

**调整指南**：
- 当前 `1200` 是 Nav2 常用值，比较均衡
- 机器人导航（算力有限）：800-1500
- 若发现指令"随机抖动"，先怀疑 N 太小，试 2000-3000
- 若 CPU 扛不住（控制频率掉到 20Hz 以下），降到 800

---

### 2. 控制时域 `time_steps × model_dt`

**物理意义**：预测未来多远的 T 秒。T = time_steps × model_dt = 2.5s。

**量化影响**：

```
T 太小（目光短浅）：
  → 看不到远处的障碍/目标 → 急转弯、短视决策
  → 比如只有 0.5s，高速下看到障碍已经来不及

T 太大（过度前瞻）：
  → 看到太远，被远处障碍"吓到"提前绕路 → 绕远、犹豫
  → 计算量线性增加
```

**关键匹配原则**：T 要 ≥ 车从当前速度减速到 0 所需时间 + 余量。

```
vx_max=2.5, ax_max=3.5 → 刹停时间 = 2.5/3.5 ≈ 0.71s
T=2.5s 是刹停时间的 3.5 倍，余量充足（合理）
```

**调整指南**：
- 低速/狭窄空间：T 可短（1-1.5s），避免绕路
- 高速/开阔场地：T 要长（2.5-4s），保证能预判
- `time_steps` 和 `model_dt` 有 trade-off——`model_dt` 太大会降低时间分辨率

---

### 3. 风险敏感参数 `temperature` (λ)

**物理意义**：控制"权重分布的集中度"，是 MPPI 最核心的调参旋钮。数学上是 KL 约束的拉格朗日乘子，也是指数权重 `exp(-S/λ)` 的温度。

**量化影响规律**：

| λ 值 | 权重分布 | 行为特征 | 适用场景 |
|---|---|---|---|
| λ → 0 | 集中在最优轨迹（退化为贪婪） | 果断、激进、易抖 | 需要快速响应 |
| λ 中等（0.3-0.7） | 集中在少数好轨迹 | 平衡 | 通用（当前 0.5） |
| λ → ∞ | 均匀分布（退化为平均） | 优柔寡断、平滑、迟钝 | 需要极稳 |

**关键洞察**：λ 的本质是**风险偏好**。
- λ 小 = **风险规避**（只信最优轨迹，但采样噪声会导致"最优轨迹"不稳定，故抖）
- λ 大 = **风险容忍**（平均所有轨迹，鲁棒但保守）

**调整指南**：
- 当前 0.5 偏果断，若画龙/抖 → 提到 0.7-0.8
- 若反应迟钝、贴线差 → 降到 0.3-0.4
- 自动驾驶（需鲁棒）：0.5-1.0
- 机器人导航（需响应）：0.3-0.7

---

### 4. 学习率 / 正则化 `gamma`

**物理意义**：控制代价 `λ·u^T Σ^{-1} v` 中控制项的权重，抑制"为了降状态代价而疯狂打控制"的行为，类似 MPC 里的控制惩罚矩阵 R。

当前 `gamma: 0.0` 意味着关闭了控制正则化。

**量化影响**：
- `gamma` 增大 → 更倾向"小控制量、平滑"，但可能追不上目标
- `gamma=0` → 允许激进控制，代价全靠 critics 约束

**调整指南**：若发现车"疯狂加速/急转"只为逼近目标，可把 gamma 提到 0.1-0.5 增加平滑性。当前注释写"稍微提高正则化，减少激进抖动"，但实际是 0.0——这是一个可尝试的优化点。

---

### 5. 噪声协方差 `std`

**物理意义**：采样探索的"广度"，`vx_std=0.6` 表示速度采样在 ±0.6 m/s 范围扩散。

**量化影响规律**：

```
std 太小 → 探索不足 → 采样轨迹都差不多 → 找不到好轨迹 → 绕路/短视
std 太大 → 探索过度 → 采样噪声大 → 加权平均后指令抖动
```

**关键匹配原则**：std 应与"任务需要的机动幅度"匹配。

```
vx_std=0.6 vs vx_max=2.5 → 探索范围是最大速度的 24%（合理）
若高速场景（vx_max 提升），std 也要同步提升
```

**调整指南**：
- 画龙/指令抖 → 降低 std（0.6→0.3-0.4）
- 贴线差/绕路 → 提高 std
- `wz_std=0.2` 相对偏小，转向探索不足时试 0.3

---

### 6. 迭代次数 `iteration_count`

**物理意义**：重要性采样的迭代轮数。每轮用上轮结果作为新采样基准。

**量化影响**：

```
iteration=1：一次采样加权（当前值，Nav2 默认）
iteration=3：三轮迭代，收敛更准，但计算量 ×3
```

**调整指南**：通常保持 1。只有在大 batch_size 不够、或强非线性模型下才考虑提高。对比赛场景，`iteration_count: 1` + 足够 batch_size 是最优性价比。

---

### 7. 加速度约束 `ax/ay/az_max`

**物理意义**：运动模型里的物理极限，限制控制量的变化率。

**量化影响**（"平稳性"最直接旋钮）：

```
ax_max 大 → 响应快，但急加速/急刹 → 不平稳
ax_max 小 → 平稳，但响应慢 → 追不上快速目标
```

**关键（当前配置的隐患）**：MPPI 的 `ax_max=3.5` 与 velocity_smoother 的 `max_accel=2.5` 不一致，会导致 MPPI 预测与现实不符，产生"犹豫"（详见全链路调参指南）。

---

### 8. critics 的 `cost_weight` 与 `cost_power`

**物理意义**：各代价项的权重和幂次，构成总代价：

```
S(τ) = Σ_i  cost_weight_i · (critic_cost_i)^cost_power_i
```

**量化影响**：

| 参数 | 作用 | 当前值 |
|---|---|---|
| `GoalCritic.cost_weight` | 到达目标的动力 | 20.0（最高，保证不迷路） |
| `PathFollowCritic.cost_weight` | 贴线跟踪 | 6.0 |
| `PathAlignCritic.cost_weight` | 方向对齐 | 4.0 |
| `ObstaclesCritic` | 障碍排斥 | repulsion 2.0 |
| `cost_power` | 代价非线性度 | 2 = 二次惩罚 |

**关键洞察**：`cost_power: 2`（二次）比 `1`（线性）对"大误差"惩罚更狠，会让 MPPI 更强烈地回避代价大的状态。GoalCritic 权重 20 远高于其他，说明"到达目标"的优先级压倒一切。

## 第三部分：参数整定指南（按场景）

### 机器人导航（当前场景）

```
目标：平稳 + 可靠到达，速度中等（2.5 m/s）
推荐：
  temperature: 0.5-0.7（偏稳）
  batch_size: 1000-1500
  time_steps × model_dt: 2-3s
  std: 最大速度的 20-30%
  ax_max 与 velocity_smoother 对齐
  GoalCritic 权重高，PathFollow/PathAlign 权重中等
```

### 自动驾驶（高速、需鲁棒）

```
目标：安全 + 平滑，速度高（10+ m/s）
推荐：
  temperature: 0.7-1.0（更保守，鲁棒优先）
  batch_size: 3000-5000（高速需更准估计）
  time_steps: 3-5s（高速需更长预判）
  std: 相对更小（减少高速下抖动）
  gamma: 0.1-0.5（增加控制平滑）
```

### 运动控制（快速机动、敏捷）

```
目标：敏捷 + 快速响应
推荐：
  temperature: 0.2-0.4（果断激进）
  batch_size: 800-1200
  time_steps: 1-2s（只看眼前，快速反应）
  std: 相对更大（探索更多机动可能）
  iteration_count: 可尝试 2-3（强机动下收敛更准）
```

## 第四部分：参数自适应调整策略

### 策略 1：基于速度的自适应 std

高速时降低 std 减少抖动，低速时提高 std 增强探索：

```
std_adaptive = std_base · (1 - v_current / v_max · 0.5)
```

### 策略 2：基于目标距离的自适应 temperature

远离目标时果断（λ 小），接近目标时平滑（λ 大），避免目标点"点头"：

```
λ = λ_base · (1 + e^(-d/d_threshold))
```

### 策略 3：基于环境复杂度的自适应 time_steps

开阔地短时域（快速反应），密集障碍长时域（充分预判）：

```
T = T_base · (1 + obstacle_density)
```

### 最佳实践总结

1. **单变量法调参**：一次只改一个参数，用 jerk（加速度变化率）量化效果
2. **先对齐物理约束**：MPPI 的加速度/速度上限必须和下游 velocity_smoother 一致
3. **temperature 是最后调的旋钮**：先定 batch_size 和时域，再用 temperature 微调果断度
4. **用日志量化，不靠感觉**：记录 jerk、收敛时间、路径贴合度，对比改参前后

## 附：核心公式速查

| 公式 | 含义 | 对应参数 |
|---|---|---|
| `x_{t+1} = F(x_t, v_t)` | 系统动力学 | `motion_model` |
| `S(τ) = Σ [C(x_t) + λ·u_t^T Σ^{-1} v_t]` | 轨迹代价 | critics + `gamma` |
| `w(τ) = exp(-S(τ)/λ)` | 权重 | `temperature` |
| `u* = Σ w(τ)·v_t / Σ w(τ)` | 最优控制（加权平均） | 全部 |
| `v_t = u_t + ε_t, ε_t ~ N(0, Σ)` | 采样 | `std` |
